## Remaining issues and tradeoffs

- **Workspace ownership remains advisory at the API write boundary.**
  `server.py` accepts authenticated workspace PUTs without verifying the writer's
  registry identity or a document revision. The serialization added here prevents
  overlapping writes from finishing in reverse order, but cannot reject a stale
  client that submits an old layout later. Enforcing ownership or optimistic
  revisions server-side would require a coordinated API/client change, including
  dashboard edits to workspaces open elsewhere.
- **UI coordination is concentrated in `main.js`.** It owns launch requests,
  saves, workspace transitions, session membership, and window registration.
  Extracting a workspace controller would make lifecycle behavior easier to
  exercise directly. Many existing frontend Python tests assert source strings
  rather than executing interactions; those are useful contracts but cannot
  establish that the rendered app works.
- The second view uses another same-origin document and therefore another set
  of UI resources and terminal connections. Hidden views intentionally remain
  alive. The second view is optional, limited to one, and is not automatically
  restored at startup. Its terminal splits remain ordinary saved layouts.
- Only named workspaces are offered when initially opening beside the primary
  view. Each view retains its existing workspace selector, so switching remains
  available. A workspace claimed by another viewer cannot be opened twice.

## Windows follow-up for 3.8.0

- The complete Windows gate passed with 392 Python tests, one platform skip,
  and 75 Node tests. No tests were deselected. Ruff, Python compilation,
  JavaScript syntax, and whitespace checks passed.
- Native WebView2 testing reproduced an exit-save race: the raw pagehide PUT
  bypassed queued autosaves, allowing an older snapshot to replace the final
  layout. The exit save now uses the same queue with keepalive. Autosave stops
  after exit starts. A Node regression and the native reproduction pass.
- Closing a named companion view now retains every owned terminal. Previously
  only scratch terminals were retained, so an untouched named terminal could
  be lost when the remaining native window closed. The native check verifies
  both retained flags and close-to-tray with real sessions.
- Native shutdown exposed a duplicate WebSocket close in Uvicorn's SansIO
  transport. `ws_protocol.py` closes the transport directly when the protocol
  is already closing or closed. Three regressions cover both states and verify
  that an open connection still receives its normal close frame.
- `scripts/smoke_workspace_views.py` runs the real desktop application on a free
  port with disposable configuration and cmd.exe PTYs. It checks both views,
  independent registry entries, dimensions, paste-to-PTY/output, split/zoom,
  focus transfer, hide/show, divider keys, stacking, failed-save retention,
  successful close/reopen, and queued exit saving. It captures WebView2 output
  to `.release-tools/native-workspaces.png` and verifies native close-to-tray.
- Visual inspection confirmed enclosed gold/blue workspaces, visible controls,
  terminal rendering and separate sidebars at the default window size.
- Ownership at the authenticated write API remains advisory. Page unload is
  best-effort; a destroyed document cannot promise completion of queued work.
  Explicit companion close waits for the save before removing its document.
  These limits remain documented rather than implying durable browser unload.
